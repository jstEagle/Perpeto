fn assign(item: WorkItem, pool: &Workers) {
  let w = pool.idle().filter(|w|
    w.can_run(&item.requires));
  // explicit ownership, one owner
  item.owner = w.first()?.id;
  events.push(Assigned(item.id));
}

From intent to evidence, in one loop

      
A project holds goals, requirements, context and feedback. Perpeto would turn that into bounded work, run it across machines, and check the result against what was asked.

      
    
        
  1. DefineDescribe the outcome, constraints and acceptance criteria.
    2. 
        
  2. PlanBreak goals into work items with owners and dependencies.
    3. 
        
  3. AssignHand bounded assignments to workers on available machines.
    4. 
        
  4. ExecuteProduce changes, artifacts, events and logs.
    5. 
        
  5. VerifyRun checks and review against each requirement.
    6. 
        
  6. LearnFeed corrections back into the project.
    7.

Running is not the same as done

        
Perpeto keeps planned, running, blocked, failed and verified apart. “Verified” is reserved for results backed by named checks. Give the mark a spin.
