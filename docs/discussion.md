# The next conversation

We should settle the identity and product promise first, then turn the answers into a mission and requirements.

## Identity

- Does Perpeto remain the name, or should we explore alternatives?
- Which direction feels right: Workshop, Current, or Commons?
- Does “software factory” describe the ambition clearly to the intended users?

## Mission and first user

- Who should get value first: an individual builder, a small software team, or an operator managing many projects?
- What outcome should they reach that is hard with their current agent workflow?
- Is the first experience creating a new project, taking over an existing repository, or both?

## Autonomy and control

- What can the factory decide independently, and which actions require a person?
- How should a person pause, redirect, or stop a project?
- How should spending, execution time, and concurrency be bounded?

## Coordination and machines

- Which agent tools and machine environments matter for the first version?
- Do users bring their own machines, use hosted workers, or need both?
- How should ownership, conflicting edits, unavailable workers, and retries behave?

## Project knowledge and evidence

- Which requirements, documents, datasets, and feedback sources must the project reference?
- What makes a requirement complete, and who can accept the evidence?
- Which events and logs must be retained, and what must stay private or local?

## First release and openness

- What is the smallest complete workflow that proves the product useful?
- Should the first interface be a CLI, a web application, or a combination?
- Which license and contribution model fit the project's goals?

No answers are assumed here. The next step is a focused discussion, followed by a mission and a small set of testable requirements.
