# Saved factory definition agent tools

Extended `packages/factory-client` with configured-project list/read/create/update operations against `/api/perpeto/factories/projects/:projectId`. Reused `validateDefinition` from the local factory definition package, so graph node/edge semantics, size limits and authority-cycle validation stay consistent with persistence. No inference or graph execution was added.

Reusable methods: `listFactories()`, `readFactory(id, {version?})`, `createFactory({id, definition})`, `updateFactory({id, expectedVersion, definition})`. Factory/project path identities validate before requests. No method accepts a project override. Create takes an explicit caller-stable ID, and update requires the exact positive expected version. Reads retain automatic safe retries; both writes send once without replay after network/transient failures. Validation produces a cloned payload and never mutates the caller's draft or expected version.

CLI adds `factories`, `factory-read --id ID [--version N]`, `factory-create --id ID --definition FILE`, and `factory-update --id ID --expected-version N --definition FILE`. A failed write preserves the JSON file. After ambiguity, read the explicit ID/current version before reconciling; the client does not silently overwrite or increment the version.

MCP adds `factory_list_definitions`, `factory_read_definition`, `factory_create_definition`, and `factory_update_definition` for ten tools total. Tool descriptions explicitly state definition storage only and no graph execution or policy enforcement. Structural schemas describe all four node types and three edge types; the shared validator performs semantic checks. Safe client errors retain HTTP status in tool failures, while raw server bodies and credentials remain excluded.

Validation: fifteen client tests pass with actual local HTTP fixtures plus CLI/MCP child processes. Added coverage for configured project routing, immutable-version query, explicit create ID and update CAS payloads, cross-project/path traversal rejection, malformed graph rejection, stale HTTP409 preserving draft and expectedVersion, no replay on transient create/update failures, full graph CLI/MCP authoring and strict override/harness rejection. No live provider call was made. Lead additionally verified create/update/list/historical reads through actual MCP subprocesses against the built runtime, stale HTTP rejection and persistence after restart. Visual editor integration is separate work.
