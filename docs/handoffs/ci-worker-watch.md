# Continuous CI worker handoff

Added `worker.js watch --config runner.json` and reusable `watchRunner` loop in `packages/factory-runner/src/watch.js`. The worker processes one job at a time, claims immediately after completion, sleeps on an empty queue, and backs off after errors. Optional machine JSON `pollIntervalMs` and `retryIntervalMs` use shared defaults and validation ranges in `packages/factory-runner/config/limits.json`. No environment configuration was added; queue and HTTP API contracts are unchanged.

`runOnce(config, parentAbortSignal)` now combines parent shutdown with its existing confirmed-lease watchdog. Claim, heartbeat and completion HTTP calls accept that cancellation signal as well. Active cancellation kills the detached command process group, withholds completion, and clears heartbeat/watchdog timers. The interrupted lease expires to `lost`, requiring explicit inspection/retry. SIGINT/SIGTERM in watch mode abort idle waits and active work and exit cleanly with code 0; configuration failures remain exit 1. The CLI emits readiness/outcome/stopped JSON events without printing credential values or raw server error responses.

Validation: all eleven runner tests pass in an isolated source copy before integration and again against the repository. Seven existing queue/worker regressions remain intact. Four new actual worker-subprocess tests use temporary Git repositories, SQLite and authenticated HTTP: a job submitted after multiple idle polls completes its pinned checkout; SIGTERM during a 60-second idle wait exits promptly; SIGTERM during execution kills both parent command and descendant, submits no completion, expires to lost and supports manual retry; repeated transient HTTP failures obey configured backoff and redact a credential-bearing response body.

Follow-up review found that the existing `once` CLI still used default signal termination, which could leave detached commands running. Both CLI execution modes now share the signal lifecycle. A fifth subprocess regression repeats active-command/descendant cancellation in `once` mode, verifies clean exit, withheld completion and eventual lost/manual-retry state. The complete runner suite now has twelve tests.

No claim is made that this installs a persistent OS service, runs Windows commands, or was tested across two physical machines. A hard kill of the worker process itself cannot execute graceful cleanup; existing lease/fencing semantics still govern recovery.

Follow-up: process-group cleanup also runs on the parent's `exit` event. A descendant inheriting stdout/stderr can keep `close` pending after its parent has exited, so waiting until `close` alone caused a false timeout. Both ignored and inherited descendant-pipe regressions pass, bringing the runner suite to thirteen tests.
